# Разработка и сборка

[Главная страница](../README.md) · [Руководство](user-guide.md) · [История изменений](../CHANGELOG.md)

## Требования

- Windows x64 и [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0).
- PowerShell 5.1 или 7 для скриптов упаковки.
- Доступ к NuGet при первом восстановлении зависимостей.

`global.json` разрешает стабильные SDK .NET 10 начиная с 10.0.100. Версия приложения задаётся в `Directory.Build.props`. Прямые зависимости указаны в файлах проектов; `packages.lock.json` фиксируют также транзитивные версии. Сведения о лицензиях находятся в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

Выпуски 0.4 и 0.5 собраны SDK **10.0.401**. Для воспроизведения используйте эту версию; версия инструментария также сохраняется в `release-manifest.json`. При другом SDK его неявные пакеты могут отличаться и вызвать ошибку locked restore — обновление lock-файлов в таком случае должно быть осознанным.

## Запуск из исходников

Выполняйте команды из корня репозитория:

```powershell
dotnet restore PcbExpo.slnx --locked-mode
dotnet build PcbExpo.slnx -c Release
dotnet run --project src/PcbExpo.App/PcbExpo.App.csproj
```

Шаблон принтера и Gerber-наборы пользователя в Git не включены. Выберите собственные файлы в интерфейсе. `150x100.cxdlpv4` в текущем каталоге или рядом с exe загружается автоматически.

## Тесты

```powershell
dotnet test PcbExpo.slnx -c Release -r win-x64
```

Тесты проверяют координаты, раскладку, полярность, компенсацию, трафарет, парсеры контуров/сверловки, состав CNC и повторное чтение CXDLPV4. Часть интеграционных тестов использует локальные `150x100.cxdlpv4` и `Gerber_Cube_PCB_Cube_2026-09-23`, если они доступны; без этих файлов соответствующие тела тестов завершаются без проверки реальных исходников. Самостоятельные проверки используют синтетические данные. Поэтому число успешно завершённых тестов само по себе не подтверждает наличие проверки на реальных файлах.

Программные тесты не заменяют физическую проверку LCD, направления изображения, проявления материала и обработки на станке.

### Проверка интерфейса

`UiRedesignTests` использует Avalonia.Headless 12.1.2 с рендерером Skia и Segoe UI. Проверяет главное окно в размерах 1560 × 940, 1366 × 768, 1280 × 672, 1100 × 700 и 1100 × 600 DIP, доступность панели команд и экспорта, сворачивание секций, смену режима, ошибку числового ввода и применение результата калибровки. При наличии локальных Gerber и шаблона дополнительно строит реальные предпросмотры и CNC, проверяет смену категории сверловки и отмену подтверждения экспорта.

Для сохранения PNG рендера и дерева контролов задайте абсолютный каталог в переменной `PCBEXPO_UI_SCREENSHOTS`, затем выполните:

```powershell
dotnet test tests/PcbExpo.Tests/PcbExpo.Tests.csproj -c Release -r win-x64 --filter FullyQualifiedName~UiRedesignTests
```

Headless-проверка не открывает окна Windows. Нативные диалоги выбора файлов, масштабирование Windows на физическом мониторе и аппаратные операции требуют отдельной проверки. Headless входит только в тестовый проект и не добавляется в пакет приложения.

## Структура репозитория

```text
src/PcbExpo.App/       интерфейс Avalonia и диагностический запуск
src/PcbExpo.Core/      импорт, координаты, растр, DXF и CXDLPV4
tests/PcbExpo.Tests/   автоматические проверки
scripts/              упаковка автономного приложения и исходников
docs/                 руководство, скриншоты и описания релизов
licenses/             тексты лицензий и уведомлений зависимостей
```

Профили и журнал сохраняются в `%LOCALAPPDATA%\PcbExpo\`. Рабочие платы, шаблоны, `.pcbexpo.json`, `.local/` и `artifacts/` исключены из Git.

## Автономный Windows-пакет

```powershell
./scripts/build-exe.ps1
```

При нестандартном расположении SDK:

```powershell
./scripts/build-exe.ps1 -DotnetPath 'C:/tools/dotnet/dotnet.exe'
```

Скрипт запускает Release-тесты, публикует `win-x64` по профилю `Windows-x64`, проверяет версию, загрузку нативных библиотек и PNG-кодека, добавляет документацию и лицензии, затем создаёт ZIP и `SHA256SUMS.txt`. Любая ошибка останавливает сборку. Каждый запуск получает отдельный каталог `artifacts/PcbExpo-<версия>-win-x64-<дата-время>-<id>/`; предыдущие результаты сохраняются.

В `app/` находятся exe, README, руководство и лицензионные файлы. В `checks/` остаются журналы проверок; они не попадают в ZIP. Шаблон по умолчанию не включается. Для личной сборки с локальным шаблоном можно явно указать `-IncludeTemplate`; перед распространением такого пакета убедитесь, что этот файл можно передавать получателям.

Exe содержит .NET Runtime. При первом запуске нативные библиотеки распаковываются в `%TEMP%/.net/`. Trimming отключён для совместимости UVtools, Avalonia и сериализации. Это стандартный механизм [single-file deployment .NET](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview).

## Диагностика

```powershell
dotnet run --project src/PcbExpo.App/PcbExpo.App.csproj -- --version
dotnet run --project src/PcbExpo.App/PcbExpo.App.csproj -- --check-runtime
dotnet run --project src/PcbExpo.App/PcbExpo.App.csproj -- --inspect './template.cxdlpv4' './gerber' --all
```

`--inspect` создаёт уменьшенные диагностические изображения в `.local/source-check/`, пропуская режимы, которым не назначены слои. Входные файлы остаются без изменений. `--check-runtime` проверяет Emgu/OpenCV и PNG-кодек. Успешный диагностический запуск возвращает код 0; ошибка — код 1.

Готовый exe использует оконную подсистему, поэтому для получения вывода в PowerShell перенаправляйте его в файл:

```powershell
$process = Start-Process -FilePath './PcbExpo.App.exe' -ArgumentList '--version' -Wait -PassThru -WindowStyle Hidden -RedirectStandardOutput './version.txt'
Get-Content './version.txt'
```

## Подготовка публикации

1. Обновите версию в `Directory.Build.props`, `CHANGELOG.md` и описание выпуска в `docs/releases/`.
2. Добавьте все изменения в индекс Git и соберите Windows-пакет. Скрипт сохраняет идентификатор этого дерева исходников, только если нет неучтённых файлов и изменений вне индекса. Просмотрите интерфейс и проверьте состав ZIP; не включайте рабочие платы, локальные профили и журналы.
3. Закоммитьте исходники и документацию, создайте аннотированный тег соответствующей версии.
4. Добавьте архив исходников и обновите контрольные суммы:

```powershell
./scripts/package-source.ps1 -ReleaseDirectory './artifacts/<каталог сборки>' -Ref 'v0.5.0'
```

5. После отправки коммита и тега на GitHub создайте Release с этим тегом, вставьте подготовленное описание и приложите Windows ZIP, архив исходников, `SHA256SUMS.txt` и `release-manifest.json`. Выпуск 0.4 имеет статус pre-release; 0.5 публикуется как обычный релиз.

Точные версии зависимостей и доступ к их исходникам перечислены в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). Скрипты готовят локальные файлы; они не отправляют изменения и не публикуют релиз на GitHub.

При намеренном изменении зависимостей обновите lock-файлы командой `dotnet restore PcbExpo.slnx --force-evaluate`, проверьте изменения версий и обновите реестр лицензий. Сборка релиза использует locked mode и не принимает незаметное изменение графа пакетов.
